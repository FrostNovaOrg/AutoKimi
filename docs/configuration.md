# 配置与审核行为

## 开关与权限模式

```toml
default_permission_mode = "manual"

[experimental]
approval_review = true

[permission.review]
timeout_ms = 90000
max_context_chars = 24000
two_stage = true
# model = "provider/model-alias"
# policy = "附加的可信操作策略"
```

配置通常位于 `~/.kimi-code/config.toml`。合并到已有文件的对应表中，勿重复定义 TOML 表。审核模型必须是已配置的模型别名；未指定时使用当前会话模型和已有认证。

| 设置                | 源码默认值   | 范围/意义                                            |
| ------------------- | ------------ | ---------------------------------------------------- |
| `approval_review`   | `false`      | 安装器和 `/auto-review on` 开启                      |
| `timeout_ms`        | `30000`      | 1000–120000 毫秒，两阶段合计；安装示例显式设为 90000 |
| `max_context_chars` | `24000`      | 4000–100000 字符的审核证据预算，不是 token 数        |
| `two_stage`         | `true`       | 快审不通过时，独立再审一次                           |
| `model`             | 当前会话模型 | 不继承主代理的 thinking effort                       |
| `policy`            | 无           | 最多 8000 字符，另附在审核系统策略中                 |

`KIMI_CODE_EXPERIMENTAL_APPROVAL_REVIEW` 或总开关 `KIMI_CODE_EXPERIMENTAL_FLAG` 可以覆盖配置。被环境变量控制时，TUI 会提示来源，无法用命令改写该覆盖。

`/auto-review on` 开启审核并切回 Always Ask；`status` 查询；`off` 恢复所选权限模式的原有审批行为。`/auto` 是官方 Never Ask，`yolo` 同样会使审核暂停。底栏状态和 `status` 可用于确认。

## 最终只有通过或拒绝

原有权限规则先执行。原本可以直接通过或明确拒绝的操作沿用原规则，只有进入待审批入口的操作交给分类器。显式 `ask` 规则在审核模式下直接拒绝；不会弹出权限批准框。

开启两阶段时，快审返回有效 `allow` 即通过；快审返回 `deny` 或内部 `ask` 时，再做一次独立完整审核。第二次不读取第一次结论，使用相同证据。最终仍不确定时转为拒绝。关闭两阶段则只做一次完整审核。

超时、模型不可用、响应无效/截断、证据超限、授权或设置在审核中变化、审计写入失败均拒绝。每轮连续 3 次拒绝，或累计达到失败阈值 2 次，会停止本轮；成功完成审核会重置基础设施失败计数，通过会重置连续拒绝计数，新轮次重置全部计数。

涉及审核配置、代理指令文件和不支持的自定义审批回调会预先拒绝。业务问答、计划或目标确认，以及登录和工作区信任等产品流程仍可能需要交互；“没有人工兜底”指被分类器处理的工具权限审批。

## 思考强度

对始终思考且支持 `low` 的模型，两阶段都使用 **low**；若该类模型不支持 `low`，使用模型默认 effort 或 `on`；其他模型设为 `off`。主代理即使使用 `max`，审核也不随之变成 `max`。快审最多 2048 输出 token，完整审核最多 4096，并受模型本身上限约束。

## 审核能看到什么

不是整段会话。每次生成一份结构化证据：

- 当前工具名、完整参数、工作目录和代理标识。
- 根代理当前上下文中最近 8 条来源确认为用户的文本请求；更早的只记录省略数量。
- 当前代理最近 8 个工具调用。单次历史参数超过 2000 字符时省略参数；总预算不够时省略整组历史调用。

不包含工具返回正文、已读取文件或脚本的正文、助手普通文字、思考内容及附件像素。压缩摘要、钩子信息和子代理消息不能建立用户授权。若“用户请求 + 当前完整操作”已超过预算，直接拒绝，不裁掉关键证据。字符预算不包含另行发送的审核系统策略。

因此，先读取脚本再执行，不能保证分类器知道脚本内容。授权发生在更早且已压缩掉的历史中，也可能误拒绝。应在当前用户请求中明确目标和允许的副作用；不要通过换工具或编码重试已拒绝的同一操作。

## 审计

每个会话目录下的 `approval-review.jsonl` 保存时间、工具标识、模型、结论、原因、耗时和证据指纹，不保存原始用户请求与工具参数。新文件权限为 `0600`，拒绝跟随最终文件的符号链接。原因仍可能包含业务信息，应按会话数据保护，不上传仓库。
