# 安全政策

[English](en/SECURITY.md) | [简体中文](SECURITY.md)

AutoKimi 是模型权限审核层，不是系统沙箱。默认只审核原权限系统产生的待审批请求；已有允许规则及关闭审核的模式会影响覆盖范围。模型可能误判，权限策略、审核预算和配置仍由使用者管理。实现细节见 [架构](architecture.md) 和 [验证限制](verification.md)。

## 支持范围

安全修复以 `main` 当前代码及其固定 Kimi 基线为准，不承诺维护旧运行包。请用 `autokimi --version` 确认源码身份，并阅读 [更新说明](installation.md#更新)。两阶段审核不是两个独立模型的安全保证。

## 报告漏洞

若仓库 Security 页提供私密漏洞报告入口，请优先使用。入口未启用时，请先在 [Issue](https://github.com/FrostNovaOrg/AutoKimi/issues) 留下不含漏洞细节的联系请求，由维护者提供非公开沟通方式；不要公开密钥、可直接利用的细节或真实会话。

报告提供受影响提交、系统/架构、审核设置、合成复现与影响范围。区别审核服务故障、模型误判和权限边界绕过，不要用真实账号或重要文件测试破坏性效果。

发现凭据泄漏时立即撤销或轮换。删除当前文件不能撤回历史、缓存及已下载副本。请勿提交 `config.toml`、OAuth 数据、安装回执、会话、原始评测或模型请求日志；仓库与历史扫描只是辅助检查，不能证明不存在所有敏感信息。
