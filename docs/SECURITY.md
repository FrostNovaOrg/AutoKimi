# 安全政策

[English](en/SECURITY.md) | [简体中文](SECURITY.md)

AutoKimi 包含模型权限审核，以及默认启用的 Bash 系统沙箱；两者覆盖范围不同。TUI 默认只审核原权限系统产生的待审批请求；已有允许规则及关闭审核的模式会影响覆盖范围。模型可能误判，权限策略、审核预算和配置仍由使用者管理。实现细节见 [架构](architecture.md) 和 [验证限制](verification.md)。

## 支持范围

安全修复以 `main` 当前代码及其固定 Kimi 基线为准，不承诺维护旧运行包。请用 `autokimi --version` 确认源码身份，并阅读 [更新说明](installation.md#更新)。两阶段审核不是两个独立模型的安全保证。

## 报告漏洞

若仓库 Security 页提供私密漏洞报告入口，请优先使用。入口未启用时，请先在 [Issue](https://github.com/FrostNovaOrg/AutoKimi/issues) 留下不含漏洞细节的联系请求，由维护者提供非公开沟通方式；不要公开密钥、可直接利用的细节或真实会话。

报告提供受影响提交、系统/架构、审核设置、合成复现与影响范围。区别审核服务故障、模型误判和权限边界绕过，不要用真实账号或重要文件测试破坏性效果。

发现凭据泄漏时立即撤销或轮换。删除当前文件不能撤回历史、缓存及已下载副本。请勿提交 `config.toml`、OAuth 数据、安装回执、会话、原始评测或模型请求日志；仓库与历史扫描只是辅助检查，不能证明不存在所有敏感信息。

无头 `exec` 强制审核、限制文件工具范围并要求 Bash 系统沙箱。默认 shell 网络关闭，域名授权由配置和调用者共同约束；文件工具与 MCP 不在 shell 沙箱中。完整进程或多租户隔离仍应由调用者提供。任务存储可能包含提示与结果，按敏感数据保管；只对受信单机调用者开放。详见[无头边界](headless.md)。

## 红队问题修复（0.3.1）

| 项目            | 修复边界                                                                                                                      |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| F-01 硬链接     | 文件工具底层拒绝多链接 inode；完整写入使用临时文件和原子替换，追加使用经 fstat 验证的描述符。审核证据包含解析路径与文件身份。 |
| F-02 版本查询   | 启动器打印静态安装身份，不执行更新工具、SDK 或运行入口。旧版非静态回执不能获得版本检查特例。                                  |
| F-03 shell 展开 | 通过系统沙箱限制真实效果，不依赖命令字面量匹配。缺少后端时拒绝执行，已知保护对象的符号链接目标及硬链接也被检查。              |
| F-04 审计别名   | 追加前检查已打开描述符为单链接普通文件，并以非阻塞方式拒绝 FIFO 等对象；无头事件日志使用同类检查。                            |
| F-05 安装链     | 固定脚本、bootstrap 摘要、源码提交及 Node 归档摘要；运行包在解包前要求独立可信摘要或绑定源码与签名工作流的 GitHub 构建证明。  |

完整写入会替换 inode 并保留普通文件模式，不承诺保留 ACL 或扩展属性；硬链接文件需先由可信用户移除别名。系统沙箱不提供通用硬链接隔离：其他预先存在的别名、恶意并发本机进程，以及 shell 之外的工具仍有独立边界。公开报告中的模型样本成功率不能证明执行安全；测试记录区分模拟服务、真实模型及未覆盖场景。
