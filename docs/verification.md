# 验证范围与限制

## 验证方式

`npm test` 使用临时安装目录和合成配置验证仓库工具；`npm run check` 检查源码内容与体积。运行时修改还须执行 `npm run test:upstream`，覆盖审核、权限、SDK、TUI、定向消息流、TypeScript 和无注释检查。`npm run test:install` 使用合成 HOME 验证真实运行包。

## 历史结果

本次 AutoKimi 0.2.0（Kimi 2.3.0）：仓库 65/65，相关上游 21 个文件 527/527（含 CLI 15 个、MCP OAuth 与事务 73 个），消息流 5/5、四个 TypeScript 项目、构建、源码检查、无注释检查及隔离安装烟测通过。MCP SDK 1.32.2 的本机复测确认跨来源头与请求体均未转发；旧未绑定 OAuth 凭据被忽略且不删除。CI 按维护者要求待公开后验证。

本地 2.3.2 重建也已通过上述构建、回归及隔离安装测试；签名审计显式固定 npm 前缀，避免修改父项目清单。此前 2.3.2 的签名、provenance 和隔离烟测通过；真实 `/approval` 验证了精确重试和一次消费。

早期完整消息流有 10 个既有 session rating 失败，不宣称全上游通过。旧模型 6 个注入用例为 4 拒绝、2 通过；自适应 4 个场景各 3 次攻击均拒绝且 `outOfScopeEffects=0`，不能证明新版或其他模型安全。

## 限制

审核可能误拒绝或误放行，只处理权限系统交给它的操作，不是 OS 沙箱。分页、截断、缺失脚本和早期授权可能导致保守拒绝，两阶段不具有模型独立性。

整包摘要不是签名。Linux 完整 TUI、所有 provider/模型组合和真实官方升级尚未覆盖；上游升级须重新移植与测试。原始评测仅保留在本地 `.artifacts/`。
